# 業務ログ（記録と稼働分析）

AIに任せた仕事を1行ずつ記録して、「どの業務でどれだけ改善したか」を可視化するスキルです。

## 1. 記録する（タスク完了時）

タスクが1つ完了するたびに、`業務ログ/log.jsonl` へ次の形式で1行追記してください（ファイルが無ければ作成）。

```json
{"date":"YYYY-MM-DD","category":"カテゴリ","task":"何をしたか（1行）","manual_minutes":60,"auto_minutes":10,"saved_minutes":50,"outcome":"成果を1行で"}
```

| 項目 | 意味 |
|------|------|
| date | 今日の日付 |
| category | 下のカテゴリから1つ選ぶ |
| task | やったことを1行で。**顧問先の実名は書かない**（「顧問先A」のようにぼかす） |
| manual_minutes | 手作業でやったら何分かかったかの見積もり |
| auto_minutes | AIと一緒にやって実際にかかった分数 |
| saved_minutes | manual_minutes − auto_minutes |
| outcome | 成果を1行で |

カテゴリ: `記帳・経理` / `申告・決算` / `顧問先対応` / `事務所運営` / `調査・分析` / `ツール開発` / `その他`

記録のルール:
- 追記のみ。既存の行を書き換え・削除しない
- 分数は正直な見積もりでよい（あとで傾向を見るのが目的。盛らない）
- 迷ったら記録する。1行10秒なので粒度は気にしない

## 2. 分析する（「稼働分析して」と言われたら）

キットの一番上のフォルダで次を実行し、生成されたHTMLをブラウザで開くよう案内してください。

```
python .claude/skills/gyomu-log/kado_bunseki.py
```

出力: `業務ログ/稼働分析.html`（削減時間の累計・月別/週別の推移・カテゴリ別のレバレッジ・曜日別・削減トップのタスク）

## 3. 結果の説明のしかた

- 削減時間は自己申告の見積もりなので**甘め（大きめ）に出る**。絶対値を自慢する数字として扱わず、「傾向・カテゴリの構成・推移」を見るよう必ず添える
- レバレッジ（手作業想定÷AI実働）が高いカテゴリ＝「AIに任せる価値が大きい仕事」。低いカテゴリ＝「まだ人が張り付いている仕事」なので、次に仕組み化する候補として提案する
- 記録が少ない週は「AIに頼まなかった週」か「記録を忘れた週」。責めずに記録の習慣づけを促す
