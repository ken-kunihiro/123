# MF帳簿点検ハイライト

マネーフォワード クラウド会計の**総勘定元帳・補助元帳・残高試算表・推移表**を開いたときに、
気になる行を自動でハイライトするChrome拡張。確認し終えた指摘はメモを付けて色を消せる。

freee向けの同種拡張のMF版として、事務所の帳簿レビューの一次点検を画面上で終わらせるために作った。
**読み取り専用**（GETのみ）。MFへの書き込み・変更は一切しない。

## 入れ方

1. Chromeで `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をON
3. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダ（`mf-chobo-extension`）を選ぶ
4. MF会計で元帳・試算表・推移表を開く。右下に「点検 n件」ボタンが出れば動いている

更新したときは `chrome://extensions` の再読み込みボタン（↻）を押す。

## 見るところ（7観点）

| 画面 | 観点 | 内容 |
|------|------|------|
| 元帳 | マイナス金額 | 借方・貸方にマイナス計上がある行 |
| 元帳 | 補助科目の未選択 | 営業債権・債務（売掛金・受取手形・未収入金・買掛金・支払手形・未払金・前受金・前渡金など）で補助科目が空 |
| 元帳 | 消費税区分 | 課税仕入のはずの科目が対象外・非課税／不課税のはずの科目が課税／不自然な軽減8% |
| 元帳 | 消耗品費・修繕費 | 消耗品費10万・20万・30万／修繕費20万・60万の各ライン超え |
| 試算表 | 残高が逆向き | 期末残高がマイナス（貸借が逆） |
| 推移表 | トレンド崩れ | 他の月の中央値の3倍超、または1/3未満（差額10万円超） |
| 推移表 | 固定費のブレ | 役員報酬・地代家賃・保険料など定額科目の増減、計上もれの月 |

色は2段階。**赤＝そのまま放置しにくいもの**、**橙＝正しいこともあるが目視したいもの**。

### 事務所ルールに合わせている点

- **取引先欄の空欄は指摘しない**。MFでは取引先マスタを使わず、補助科目に取引先名を入れる運用のため。代わりに営業債権・債務の補助科目が空のときだけ出す
- **通信費は消費税区分チェックの対象外**。海外SaaSを通信費・対象外で計上するのが事務所の正なので、指摘すると全部が赤くなる
- 支払報酬・諸会費・福利厚生費も同じ理由で税区分チェックから外している
- 閾値・科目リストは [`src/rules.js`](src/rules.js) の先頭にまとめてあるので、顧問先ごとに合わなければそこだけ直す

## 使い方

- **セルの赤・橙**：その行に指摘がある。セル内の「確認」バッジを押すとメモ欄が開く
- **メモを書いて「確認済みにする」**：ハイライトが消えて、バッジが「済」になる。次に同じ画面を開いても色は付かない
- **「ハイライトを戻す」**：確認済みを取り消して元に戻す
- **右下の「点検 n件」**：観点別の件数と一覧。項目をクリックするとその行までスクロールする。観点のチップを押すと絞り込み

確認済みの記録は**事業所（cti）ごと**にブラウザのローカル領域へ保存される。
MFにも外部サーバーにも送らない。キーは「画面種別｜科目名｜取引No（または科目・月）｜観点」なので、
同じ取引に再度当たれば確認済みのまま、金額や税区分を直せば別の指摘として出直る。

```

src/rules.js       判定ロジック（DOMに触らない純粋関数）。閾値・科目リストはここ
src/store.js       確認済みメモの保存（chrome.storage.local）
src/content.js     画面判別・表の読み取り・ハイライト・パネル・メモUI
src/styles.css     見た目（Apple風ベース。ハイライトの赤橙は機能色として例外）
test/rules.test.js rules.js の判定テスト。`node test/rules.test.js`
test/harness/      MFと同じURL・同じ表構造のダミー画面。ブラウザでの動作確認用
```

### 動作確認

判定ロジックだけなら `node test/rules.test.js`。

画面まわり（ハイライト・バッジ・パネル・メモ保存）を確かめるときは、
MFにつながずローカルのダミー画面で動かす。

```
python test/harness/server.py 8766
```

`http://127.0.0.1:8766/books/general_ledger` `/books/subsidiary_ledger`
`/balance_books/tb` `/balance_books/tb_transition_monthly` を開くと、
拡張と同じ `src/*.js` がそのまま読み込まれる（`chrome.storage` は localStorage で代用）。
ダミーの数字だけを置いていて、顧問先の実データは一切入れない。

### 表の読み方

MFの画面はRails製のHTML（試算表・推移表）とReact＋CSS Modules（新元帳）が混ざっていて、
クラス名（`table___mKNt2` など）はビルドのたびに変わる。そのため列の特定は二重にしている。

1. **ヘッダーの文字**で列を決める（「補助科目」「税区分」「借方」「貸方」…）
2. 取れなければ**クラス名の部分一致**（`colSubItem` / `colExcise` / `colAmount`）

元帳の明細行には勘定科目名が出ないので、hidden の `own_side_item_id`（plainId）を
`/api/v1/categorized_items` で科目名に引き直している（1日1回キャッシュ）。
このAPIは `cti`（事業所トークン）が必須で、`cti` は画面内の `input[name=cti]` から取っている。
`mf-bs-drawer` と同じ取り方。

SPAで表が描き直されるので MutationObserver で再点検する。
自分が入れたバッジによる変化は無視して、無限ループしないようにしている。

## 制限・分かっていること

- **少額特例・優良電子帳簿の表示は入れていない**。MFの事業者設定（`/offices/edit`）に少額特例の設定項目が無く、
  優良電子帳簿の要件（仕訳履歴保存）は取れるが元帳画面からは参照できないため、いまは観点から外した
- 推移表のBS科目はトレンド判定しない（残高は増減して当然のため）
- 補助元帳では科目名が取れないことがある。その場合は科目名なしで取引Noだけで記録される
- 閾値は事務所の一般的な基準。顧問先ごとの実情に合わせるときは `src/rules.js` を直す
