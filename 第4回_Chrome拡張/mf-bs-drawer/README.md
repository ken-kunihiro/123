# MF BSサイドドロワー

マネーフォワード クラウド会計の「連携サービスから入力」画面の右側に、**消し込み対象のBS残高**をスライド表示するChrome拡張。科目行を開くと、その科目の元帳から**補助科目別の内訳**を集計して出す。

この画面は**URLが2本ある**。どちらもパンくずは「自動で仕訳 > 連携サービスから入力」で見た目もほぼ同じだが、実体は別ルート。両方を `matches` に入れてある。

| URL | 中身 |
|---|---|
| `/transaction_journals` | 明細一覧（通帳・カード他）。**実際に消し込みをする画面はこっち** |
| `/journalable_dists` | ビジネスカテゴリ側の入口 |

`20_事務所/tools/freee-bs-drawer` のMF版。起票中に試算表へ画面を切り替えなくても、残高と内訳をその場で確認できるようにするのが目的。

## できること

- 右端の「BS残高」タブをクリックするとドロワーが開く（既定ではMF本文を左に押し出して重ならないようにする）
- ドロワーの**左端を左右にドラッグすると幅を変えられる**（既定380px。ダブルクリックで既定に戻る）。幅は保存される
- 消し込み対象3グループの残高一覧。グループごとに小計つき
- 科目行クリックで元帳を取得し、**補助科目別の内訳**を表示
- 内訳の行をさらにクリックすると、**その補助科目の元帳明細**（日付・相手科目・摘要・金額）をドロワー内に展開
- 展開した明細の見出しから、MFの元帳を**その補助科目で絞り込んだ状態**で別タブで開ける
- 明細の**日付をクリックすると、その1日に絞った元帳**が別タブで開く。ほぼその行だけになるので「詳細」を1回押せば仕訳が出る
- 科目名での絞り込み検索
- 入力欄に勘定科目を打つと、ドロワー内の該当科目行を自動ハイライト＋スクロール
- 残高0の科目は既定で非表示（フッターのボタンで表示に切替）
- 開閉状態は覚えるので、**F5で更新すると開いた状態で戻り、残高も取り直す**（記帳したぶんが反映される）

## 表示する科目（消し込み対象のみ）

freee版と同じ3グループ。残高そのものを眺めるツールではないので、預貯金・棚卸資産・固定資産などは表示しない。

| グループ | 拾う科目名（部分一致） |
|---|---|
| 営業債権 | 受取手形・売掛金・売掛債権・未収入金・未収金・未収収益 |
| 営業債務 | 支払手形・買掛金・未払金・未払費用 |
| 借入金 | 借入金（短期・長期・役員借入金を含む） |

増やしたいときは `content.js` の `GROUPS` に1行足す。`side` は残高の向き（`asset` = 借方プラス／`liability` = 貸方プラス）で、内訳集計の符号に効く。

## インストール

1. Chromeで `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をON
3. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダ（`20_事務所/tools/mf-bs-drawer`）を選ぶ
4. MFクラウド会計の「連携サービスから入力」画面を開き直す

## データの取り方: 残高はHTML、内訳はJSON API

MF会計は画面によって性格が違う。**試算表だけがサーバーサイドHTML**で、元帳・マスターはReactのSPA（HTMLに表が入っていない）。そこで2系統を使い分けている。

| 用途 | freee版 | MF版 |
|---|---|---|
| 残高 | `/api/p/reports/trial_balance_sheet`（JSON） | `/balance_books/tb`（**HTML表をパース**） |
| 内訳の元 | `/api/p/reports/general_ledgers/show`（JSON） | `/api/v1/ledger_entries`（JSON） |
| 科目・補助科目・取引先の名前 | 元帳レスポンスに同梱 | `/api/v1/categorized_items` `/api/v1/sub_items` `/api/v1/trade_partners` を**別途取得**して辞書にする |
| 会計期間 | `/api/p/fiscal_years` | 試算表HTMLの `month_search_from` / `month_search_to` |
| 事業所の固定 | `company_id` を渡さない | `cti`（試算表HTMLの `input[name=cti]` から取る） |
| 内訳の軸 | 取引先別・品目別 | **補助科目別** |

元帳をHTMLで取ろうとすると失敗する。`/books/general_ledger` は HTTP 200 を返すが `<table>` が1つも無い（Reactのマウント先が空）ので、必ずJSON APIを使う。

## 事業所トークン `cti`

MFは事業所を `cti`（22文字のトークン）で持つ。ところが**「連携サービスから入力」画面のURLには `cti` が付いていない**。

そこで、最初は `cti` を付けずに `/balance_books/tb` を叩き、**返ってきたHTMLの `input[name=cti]` を正本にする**。MFは `cti` 無しなら「いまログインしている事業所」を返すので、これで画面と必ず同じ事業所になる。以降のAPIリクエストと画面リンクにはこの `cti` を必ず付けて、事業所の取り違えを防ぐ。

## 会計期間の決まり方

期間の正本は**試算表画面が出している月セレクト**（`month_search_from` = `2025/11` / `month_search_to` = `2026/10`）。期首＝from月の1日、期末＝to月の月末に直して使う。

freee版は「今日」で期末を切っていたが、MF版は試算表が出している期間をそのまま使う。**試算表と元帳の期間がずれると内訳合計が残高と合わなくなる**ため。会計年度のラベル（「2025年度（11月1日〜10月31日）」）はHTML本文から正規表現で拾って表示に添えているだけで、計算には使わない。

## 試算表HTMLの構造

`table.ca-balance-books-bs-trial-table` は**4つある**。ヘッダーだけを持つテーブル（`rows.length === 1`）が各表の直前に入るので、**複数行ある最初のテーブルがBS本体**（PLはその次）。

列は `[科目, 前期残高, 借方金額, 貸方金額, 期末残高, 構成比]`。列位置は `table.ca-balance-books-double-tiered-table-thead` の見出しから「期末残高」を探して決める。

| 行のクラス | 中身 | 扱い |
|---|---|---|
| （クラスなし）＋ `label-indent-01` / `-03` | 勘定科目 | 一覧に出す。リンクから `own_side_item_id` を取る |
| `sub-item-row` ＋ `label-indent-04` | 補助科目 | 読み飛ばす（内訳は元帳APIから取るため不要） |
| `report-unit-summary` | 小計・合計 | 読み飛ばす |

## IDが2系統ある

MFの勘定科目には**数値ID（`plainId`）と22文字トークン（`id`）の2つ**がある。

| | 使う場所 |
|---|---|
| `plainId`（例 `12345678`） | 試算表HTMLの科目リンク `own_side_item_id` |
| `id`（例 `4TGKBNGkMFXvTUYgGKcwfQ`） | APIの `own_side_ledger_account_id` |

試算表から拾えるのは `plainId` のほうなので、`/api/v1/categorized_items` が返す `{id, plainId, label}` で**変換表を作ってから元帳を引く**（`attachLedgerIds`）。念のため科目名からも引ける保険（`ledgerIdByName`）を持たせている。

## 元帳API `/api/v1/ledger_entries`

GET・`Accept: application/json`・`credentials: include`。

| パラメータ | |
|---|---|
| 必須 | `cti` / `own_side_ledger_account_id`（22文字）/ `recognized_at_from` / `recognized_at_to` |
| その他 | `is_realized=true` / `exclude_excise=true` / `page` / `per_page` |
| 絞り込み（有効） | `own_side_ledger_sub_account_id` / `own_side_trade_partner_id` |
| 絞り込み（**無視される**） | `trade_partner_id` / `own_side_sub_item_id` |

レスポンスは `{data: {ledgers: [...], balance_value}, metadata: {pagination: {total_pages, ...}}}`。ページングの停止条件は `total_pages`（freee版と違い、この数字は信用してよい）。上限は20ページ×200件（`MAX_LEDGER_PAGES`）。

### 期首残高は `data.balance_value`

繰越行という形では返らない。**1ページ目の `data.balance_value` が期首残高**で、これは資産でも負債でも正の値（試算表の表示と同じ向き）なので、負債の符号反転を掛けずにそのまま足す。2ページ目以降にも同じ値が入ってくるので、**採用するのは1ページ目だけ**（二重計上の防止）。

### 明細に名前が入っていない

`own_side` / `other_side` は**IDしか持たない**（`{ledger_account_id, ledger_sub_account_id, trade_partner_id, department_id, ...}`）。表示名は起動時に取った3本のマスター辞書（`state.names`）で引く。相手科目が複数あるときは `other_side_is_various_accounts: true` が立つので「諸口」と出す。

### `ledger_sub_account_id` に部門IDが混ざる

補助科目を使っていない明細では、`own_side.ledger_sub_account_id` に**部門のID**が入って返ってくることがある。そのまま名前を引くと空文字になって別バケットに割れるので、`knownId()` で**補助科目マスターに存在するIDだけを採用**し、無ければ「補助科目なし」に寄せている。取引先IDも同じ扱い。

### 同一科目内の振替

`dr_value` と `cr_value` の**両方に同額**が入る明細がある（同一科目内の振替）。MF自身も元帳画面で1行に借方・貸方の両方を出し、残高を動かさない表示をしているので、この拡張も素直に `dr − cr`（差引0）で扱う。片側ずつ分けて集計するとMFの見え方とずれる。

### 符号の検算

売掛金で実測。`35,130,550`（期首）＋ `94,171,395`（借方）− `147,158,445`（貸方）= `-17,856,500` で試算表の期末残高と一致。

2026-09-08、対象事業所の**7科目すべてで内訳合計と試算表残高の差額が0**であることを実データで確認済み（売掛金・未収入金・短期借入金・未払金996行・未払金(業務委託)・長期借入金・役員借入金）。

## 絞り込みリンク: 画面ごとに効くパラメータが違う

同じMFでも総勘定元帳と補助元帳で受け付けるパラメータが違う。**実測で確認した結果**が下記。

| 画面 | 効くパラメータ |
|---|---|
| `/books/general_ledger` | `own_side_ledger_account_id`（`own_side_item_id` でもリダイレクトで通る）・`own_side_trade_partner_id`・日付・`per_page`・`page`。**`own_side_ledger_sub_account_id` は無視される** |
| `/books/subsidiary_ledger` | `own_side_ledger_sub_account_id` が効く。MF自身は `group_by_ledger_sub_account=true` も付ける |

そのため**補助科目で絞るときだけ `/books/subsidiary_ledger` に切り替える**。取引先で絞るときは総勘定元帳のままでよい。freee版と違い、両方の軸で絞り込みリンクを張れる。

リンクを張る条件は `bucket.filterId` が `null` でないこと。「前期繰越」「取引先なし」「補助科目なし」の3バケットは絞れないので、科目全体の元帳に落とす。

### 仕訳（伝票）には固有URLが無い

MFの元帳の「詳細」ボタンは**フォーム送信**で、`location` は変わらない。freeeの取引モーダルと同じで、**伝票への直リンクは作れない**。

そこで明細の**日付をリンク**にして、`recognized_at_from` = `recognized_at_to` = その行の日付（バケットの絞り込みIDがあればそれも足す）にした元帳を開くようにしている。開いた先は目的の1行だけになるので、「詳細」を1回押せば仕訳が出る。

## 元帳ドリルダウン

内訳の行を開くと明細が出るが、ここでAPIは叩いていない。内訳を集計した時点で元帳を全件取ってあるので、その行データをそのまま並べているだけ。画面を行き来しないのがこの拡張の目的なので、ドリルダウンでも新しい通信は増やさない。表示は先頭200件（`MAX_LINES_SHOWN`）まで。

## 内訳は「期末残高の内訳」ではない

**期首残高は科目単位でしか取れない**（`data.balance_value`）。補助科目別・取引先別の期首残高はAPIから取れないので、内訳は「**前期繰越を1バケット＋期中の増減**」という形になる。合計は期末残高と一致するが、各バケットの数字はその取引先／補助科目の期末残高そのものではない。

試算表には補助科目別の期末残高があるのでそちらに寄せることもできるが、**科目行の残高（元帳ベース）と内訳（試算表ベース）で数字の出どころが変わって検算にならない**ので採らなかった。

## 内訳合計が試算表残高と合わないとき

内訳の下に**差額**を表示する。隠さない。残るとしたら次の原因。

- 元帳の行数が取得上限（`MAX_LEDGER_PAGES` = 20ページ × 200件）を超えている
- MF側の刷新でAPIのレスポンス構造・試算表HTMLの構造が変わった
- 試算表の期間表示と元帳の取得期間がずれている

## MFのCSSに潰される: `table-layout: fixed`

MFのページCSSが `table` に **`table-layout: fixed`** を当てている。この指定だと列幅は最初の行の指定値だけで決まり、中身の必要幅（min-content）が無視される。内訳テーブルの金額列は「できるだけ狭く」の意味で `width: 1%` を指定しているので、**実測6px**まで潰されて数字がセルの外に出てしまっていた（2026-09-08 発覚）。

`.hkmf-bdtable { table-layout: auto !important }` で戻している。修正後は金額列が必要な80pxを確保し、ドロワー幅300pxまで縮めても横スクロールは出ない。

拡張はMFのページに寄生する以上、**MF側のグローバルCSSがドロワー内部にも降ってくる**。似た症状（要素が潰れる・余白が消える）を見たら、まず computed style を疑う。

## 幅の変え方

ドロワーの左端に幅9pxの掴み代（`.hkmf-grip`）がある。左右にドラッグすると幅が変わり、ダブルクリックで既定の380pxに戻る。

幅は `html` 要素のCSS変数 `--hkmf-w` として持たせている。ドロワー本体の `width` と、押し出しモードの `body { padding-right }` が同じ変数を見ているので、変数を書き換えるだけで**ドロワーの左端とMF本文の右端が必ず一致する**（実測: 幅520pxのとき ca-container 857px・ドロワー左端857px）。

下限は300px、上限は「画面幅 − 320px」。画面が狭いときに広げすぎてMFが触れなくなるのを防ぐため、ウィンドウのリサイズ時にも上限へ収め直す。幅は `hkmf_width` として保存する。

## 開閉状態とリロード

開閉（`hkmf_open`）・押し出し（`hkmf_pushed`）・幅（`hkmf_width`）は `chrome.storage.local` に持つ。ページを読み込んだときだけ復元処理が走るので、**F5で更新すると「開いた状態で復元 → 残高を取り直す」**が必ず対になる。記帳してからF5を押せば、その結果が残高に乗る。元帳のキャッシュ（`state.ledgerCache`）も残高の取り直しと同時に捨てる。

戻る／進むでbfcacheから復帰したときはスクリプトが動き直さないので、`pageshow`（`persisted`）でも取り直している。

開閉・押し出しの判定はDOMではなく `state` を正本にしている。本文を差し替えられた瞬間にDOMを見ると「閉じている」と誤認して、建て直したドロワーが**中身が空のまま**になるため。

## 制約・注意

- **読み取り（GET）専用**。MFへの書き込みは一切しない。外部への送信もしない
- 使っているのは公開APIではなく**画面の内部API・内部HTML**。MF側の刷新で壊れることがある。壊れたら直す前提のツール
- MFは取引先マスターを使わず**補助科目に相手先名を入れる運用**なので、内訳の軸は補助科目別だけにしている（2026-09-08 けんとさん指示）。取引先別の集計コード自体は残してあるので、content.js の `AXES` に `['partner', '取引先別']` を足せばタブが復活する
- 「押し出す」モードでMFのレイアウトが崩れたら、ドロワー上部の「押し出す」ボタンをOFFにすると重ねて表示するモードになる

## 押し出しモードと `ca-container` の固定幅

明細一覧（`/transaction_journals`）の `div.ca-container` は **`min-width: 1360px` の固定幅**。`body` に `padding-right` を足しても縮まず、MFの本文がドロワーの下に潜り込んで**右端の「登録／対象外」ボタン列が触れなくなる**（`html` 側に横スクロールも出ない）。

そこで押し出しモードのときだけ `div.ca-container` の `min-width` を外している。素直に縮んだうえで、はみ出た列は `.ca-main-container` が持つ `overflow-x: auto` の内部横スクロールで届く（実測: ca-container 1360 → 997、テーブルは内側スクロール、ページ全体の横スクロールは出ない）。
