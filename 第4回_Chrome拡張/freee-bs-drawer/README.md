# freee BSサイドドロワー

freee会計の「自動で経理」画面（`/wallet_txns`）の右側に、**消し込み対象のBS残高**をスライド表示するChrome拡張。科目行を開くと、**取引先別・品目別の内訳**（freeeの試算表と同じ数字）と、その明細を出す。

起票中に試算表へ画面を切り替えなくても、残高と内訳をその場で確認できるようにするのが目的。

## できること

- 右端の「BS残高」タブをクリックするとドロワーが開く（既定では freee本文を左に押し出して重ならないようにする）
- 消し込み対象3グループの残高一覧。グループごとに小計つき
- 科目行クリックで**取引先別／品目別**の内訳をタブ切替で表示。金額は試算表の内訳APIそのものなので、**freeeの試算表画面と必ず一致する**（期首残高も取引先ごとに配分済み）
- 期中に動きがなくても、期首から残高が残っている取引先はちゃんと出る
- 内訳の行をさらにクリックすると、**その取引先／品目の元帳明細**（日付・相手科目・摘要・金額）をドロワー内に展開。先頭に期首残高を「前期繰越」として置く
- 展開した明細の見出しから、freeeの元帳画面を**その取引先／品目で絞り込んだ状態**で別タブで開ける
- 明細の**日付をクリックすると、その1日に絞った元帳**が別タブで開く。ほぼその行だけになるので「詳細」を1回押せば伝票が出る
- 検索は**科目／取引先の2モード**。「科目」は一覧の絞り込み、「取引先」は**全科目を横断して取引先名で探す**（下記）
- 入力欄に勘定科目を打つと、ドロワー内の該当科目行を自動ハイライト＋スクロール
- 残高0の科目は既定で非表示（フッターのボタンで表示に切替）
- 開閉状態は覚えるので、**F5で更新すると開いた状態で戻り、残高も取り直す**（記帳したぶんが反映される）

## 取引先名で横断検索する（2026-09-09追加）

入力欄の左のpillを「取引先」に切り替えると、**表示中の全科目を横断して取引先名で検索**できる。結果は「取引先 → その取引先の残高がある科目」の形で並び、科目行を開けばこれまでどおり元帳明細が出る。「この会社、どの科目にいくら残ってる？」を科目を1つずつ開かずに出すのが目的。

- インデックスは**取引先別の内訳API（試算表）だけ**で作る。1科目1リクエストで済み、元帳は取らない
- 同時実行は4本（`runPooled`）。集計中は「取引先を集計中… n / m科目」を出す
- 一度作ったインデックスはメモリに持つので、2文字目以降の打鍵で通信は発生しない
- 残高を取り直す（再取得・F5）と**インデックスも捨てる**ので、次に取引先モードに入ったときに作り直す
- 部分一致・大文字小文字は無視。`tag_id` が `0` の行は「（取引先なし）」という名前で検索できる
- **残高0の科目行も落とさない**。期首から残っていた債権を今期に回収し切った取引先は「0円」で出るので、消し込み済みであることがその場で確認できる（金額は薄字）
- 内訳APIを取れなかった科目があったら、フッターに「うちN科目は内訳を取得できなかったので結果に入っていないよ」と出す。黙って結果から欠かさない
- 明細（元帳）は**行を開いたときだけ**取る。科目モードと同じ `loadBreakdown` を通し、その取引先のバケット（`tag_id` 一致。`0` は「未選択」バケットに解決）を既存の明細描画に渡すので、元帳リンク・日付リンクの挙動もそのまま

科目行の自動ハイライトは科目モードのときだけ動く（取引先モードでは科目行が並んでいないため）。

## 表示する科目（消し込み対象のみ）

「自動で経理」で明細を消し込む先だけを出す。残高そのものを眺めるツールではないので、預貯金・棚卸資産・固定資産・有価証券などは表示しない（2026-09-08 けんとさん指示で10グループから絞り込み）。

| グループ | 拾う科目名（部分一致） |
|---|---|
| 営業債権 | 受取手形・売掛金・売掛債権・未収入金・未収金・未収収益 |
| 営業債務 | 支払手形・買掛金・未払金・未払費用 |
| 借入金 | 借入金（短期・長期・役員借入金を含む） |

増やしたいときは `content.js` の `GROUPS` に1行足す。`side` は残高の向き（`asset` = 借方プラス／`liability` = 貸方プラス）で、内訳集計の符号に効く。

意図的に外しているが消し込みはする科目（必要になったら足す）:

| 科目 | 消し込む場面 |
|---|---|
| 預り金 | 源泉所得税・住民税・社会保険の納付 |
| 未払法人税等・未払消費税等 | 税金の納付（`未払` で始まるが3グループの名前から外れるため未収録） |
| 未収還付法人税等・未収還付消費税等 | 還付金の入金 |
| 仮払金・立替金・前渡金 | 精算・充当 |

## インストール

1. Chromeで `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をON
3. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダ（`20_事務所/tools/freee-bs-drawer`）を選ぶ
4. freeeの「自動で経理」画面を開き直す

## 開閉状態とリロード

開閉（`hkbs_open`）と押し出し（`hkbs_pushed`）は `chrome.storage.local` に持つ。ページを読み込んだときだけ復元処理が走るので、**F5で更新すると「開いた状態で復元 → 残高を取り直す」**が必ず対になる。記帳してからF5を押せば、その結果が残高に乗る。元帳のキャッシュ（`state.ledgerCache`）も残高の取り直しと同時に捨てる。

戻る／進むでbfcacheから復帰したときはスクリプトが動き直さないので、`pageshow`（`persisted`）でも取り直している。

開閉・押し出しの判定はDOMではなく `state` を正本にしている。freeeはSPAで本文ごと差し替えることがあり、その瞬間にDOMを見ると「閉じている」と誤認して、建て直したドロワーが**中身が空のまま**になるため。建て直し（`mount`）では `state` を反映し直したうえで、すでに持っている残高を描き直す。

## 会計期間の決まり方

期間の正本は `/api/p/fiscal_years`。試算表を先に開いていなくても、この拡張だけで期首・期末・会計年度IDが揃う。

1. `/api/p/fiscal_years` を **`company_id` を付けずに**叩き、いまログインしている事業所の年度一覧を取る（`fy_code` が `start` の開始残高枠は除外）
2. その中から今日を含む年度を選ぶ。無ければ `status: current`、それも無ければ期末が最新の年度
3. 基準日は「試算表画面で見ていた日」（`capture.js` が控える）→ 無ければ今日。どちらも年度の外には出さない
4. 内訳は期首から積むので、期間の頭は**必ず選んだ年度の期首**にする

### `fiscal_year` パラメータの罠

試算表APIも元帳APIも `fiscal_year` が**必須**で、渡さないと `400 ACC-903-999-0001`「Fiscal yearを入力してください」で落ちる。しかも中身は**西暦ではなく会計年度のID**（例 `13197970`）で、採番は事業所ごとに違う。他所から持ち込まず、必ず `fiscal_years` から取り直す。

元帳APIだけは2つ使い分けがある。`fiscal_year_id` が年度のID、`fiscal_year` が西暦（`year_seq`）。

## 事業所の取り違え防止

- 残高・元帳・年度のAPIには **`company_id` を一切渡していない**。渡さなければfreeeは「いまログインしている事業所」を返すので、自動で経理画面と必ず同じ事業所の数字になる
- 試算表からキャプチャした年度IDは、**いまの事業所の年度一覧に含まれているときだけ**採用する。含まれていなければ別事業所のものなので捨てて、自前で今日を含む年度を選び直す。これが事業所一致の確認を兼ねる

## 試算表レスポンスの構造

BSは3段構造になっている。グループ判定を子の名前でやると預貯金が丸ごと空になるので注意。

| `line_type` | 中身 | 例 |
|---|---|---|
| `account_group` | 決算書の表示科目。**グループ判定はここの名前で行う** | 現金及び預金 |
| `breakdown_account_item` | 実際の勘定科目。**元帳はこの名前で引ける** | 東邦銀行 |
| `breakdown` | 「取引先別」「品目別」などの見出し行。金額は空なので読み飛ばす | 取引先別 |

子がある表示科目は子を並べ、子がない表示科目は自分自身を1行として出す。金額は `report_lines` が**トップレベル**に返る（`data.report_lines` ではない）。資産／負債の向きは各行の `entry_side`（`-1` = 資産、`1` = 負債）で判定する。

## 内訳の金額は元帳ではなく試算表から取る

**内訳（取引先別・品目別）の金額の正本は `/api/p/reports/trial_balance_sheet_element`。** freeeの試算表画面が科目を「取引先別」に展開したときに叩いているAPIで、取引先ごとに 期首・借方・貸方・期末 が返る。

| パラメータ | 値 |
|---|---|
| `display` | `partner` = 取引先別 ／ `item` = 品目別 |
| `name` | 勘定科目名（試算表の `breakdown_account_item` の名前） |
| `fiscal_year` / `start_date` / `end_date` | 試算表APIと同じ |
| `base_amount` / `pre_year_base_amount` | 構成比の分母。内訳の金額には効かないので `0` でよい |

返るのは `report_tags`（トップレベル）。各要素の `tag_id` が取引先ID／品目IDで、**`0` は「未選択」**（取引先や品目を付けていない行）。金額は `columns` の `period` が `start_date` / `end_date` の要素から拾う（試算表本体と同じ形）。負債科目でも試算表の表示と同じ向きの正の値が返るので、符号反転はしない。`company_id` と `base_level` は省略できる。

### 元帳を積み上げる方式をやめた理由（2026-09-08）

元々は元帳を全件取って集計していたが、**期首残高を取引先に配れない**。元帳の繰越行（`is_carry_over: true`）は科目に1行あるだけで取引先を持たないため、「前期繰越」という架空の1バケットに全額が溜まり、期首から残っていた債権を今期に回収しただけの取引先が**マイナス残高に見える**（実際の残高は0）。ユーツーテックの売掛金／ジャパンカーゴネットワーク有限会社が -1,045,000 と出ていたのがこれ。

いまは元帳を**明細のドリルダウン専用**に降格させ、繰越行は読み飛ばしている。期首残高は各バケットの先頭に「前期繰越」の合成行を1本置いて見せる（件数には数えない）。

なお繰越行そのものの形は、フォールバック（下記）でだけ使うので覚えておく。**`debit` も `credit` も 0 で、`balance` に期首残高**が入り、この `balance` は資産でも負債でも正の値。

### 明細をどのバケットに入れるか

**その行が自分で持っているIDだけで決める**（`partner_id || 0` / `item_id || 0`）。相手行（`corresponding_partner_name`）から名前を借りる推測はしない。freee側の集計は自分の行のIDで束ねているので、借り物で束ねると金額もリンクもfreeeの画面とズレる。

### フォールバック

内訳APIが落ちたときだけ、旧方式（元帳の積み上げ）に落ちる。この場合は期首が配分されないので、**画面に断り書きを出す**。黙って違う数字を見せない。

### ページング

元帳のページングの停止条件は「返ってきた件数が `per_page` に満たなくなったら終わり」。レスポンスの `total` は繰越行を含まない別カウントで実際の明細数と一致しないので、停止条件には使わない（使うと末尾を取りこぼす）。`per_page=500` が効かず100件しか返さない事業所があるので、その場合だけ100件で回し直す。

## 元帳ドリルダウン

内訳の行を開くと明細が出るが、ここでAPIは叩いていない。内訳を出す時点で元帳を全件取ってあるので、その行データをそのまま並べているだけ。画面を行き来しないのがこの拡張の目的なので、ドリルダウンでも新しい通信は増やさない。表示は先頭200件（`MAX_LINES_SHOWN`）まで。

### freeeの元帳画面を開くリンク

| | 値 |
|---|---|
| URL | `/reports/general_ledgers/show`（APIと同じパスの `/api/p` 抜き） |
| 期間 | `start_date` / `end_date` |
| 年度 | `fiscal_year_id` と `fiscal_year` の**両方に年度ID**を入れる |
| 科目 | `name` |
| 絞り込み | `partner_ids` / `item_ids`（画面URLは単数値でよい） |

**`fiscal_year` の意味が画面とAPIで逆**。APIは西暦（`year_seq`）だが、画面は年度ID。freee自身が総勘定元帳一覧からそう組み立てている。

絞り込みは**必ずIDで渡す**。`partner_name` を渡しても黙って無視されて全件が出る。なおAPI側で同じ絞り込みをするときのキーは `partner_ids[]` / `item_ids[]`（角括弧なしの `partner_ids` は「取引先IDの値が不正です」で弾かれる）。画面URLとAPIでキーの形が違う。

### 絞り込みリンクを出す条件

バケットのキーが内訳APIの `tag_id` そのものなので、**`tag_id` が0以外ならそのまま絞り込みリンクにする**。0（未選択）のバケットだけ「科目全体」の元帳リンクに落とす。

（旧方式では相手行から名前を借りていたため「全行が同じ自前IDのときだけリンクする」という判定が要ったが、自前IDで束ねるようになって不要になった。）

### 伝票（取引の詳細）には固有URLが無い

freeeの取引詳細はモーダルで、**URLを持たない**。元帳画面で「詳細」を押しても `location` は変わらず、叩いているAPIは `/api/p/deals/standard/{deal_id}` だが、対応する画面ルートは存在しない。実測（2026-09-08）で以下はすべて「ページが見つかりませんでした」になる。

| 試したURL | 結果 |
|---|---|
| `/deals/{deal_id}` | 404 |
| `/deals/standard/{deal_id}` | 404 |
| `/deals/edit/{deal_id}` | 404 |
| `/manual_journals/{id}` / `/transfers/{id}` | 404 |

取引一覧（`/deals/standards`）でも行クリックはモーダルでURLは変わらない。つまり**伝票への直リンクは原理的に作れない**。

そこで明細の**日付をリンク**にして、`start_date` = `end_date` = その行の日付、さらにバケットの絞り込みIDを足した元帳を開くようにしている。開いた先は目的の1行（＋前日繰越）だけになるので、「詳細」を1回押せば伝票のモーダルが出る。実測: 未払金／齊藤昌幸／2026-04-28 → 明細1行、預り金／品目 社会保険／2026-06-30 → 明細1行。

## 内訳合計が試算表残高と合わないとき

内訳の金額は試算表の内訳APIそのものなので、**通常この差額は0になる**。それでも合計と差額は隠さず出す。差額が出るとしたら次の原因。

- フォールバック中（内訳APIが落ちて元帳の積み上げになっている）
- freee側の画面刷新でレスポンス構造が変わった

### 実測（ユーツーテック 2026-01-01〜2026-12-31／2026-09-08）

| 科目 | 内訳バケット | 内訳合計 | 試算表残高 | 差額 |
|---|---|---|---|---|
| 売掛金（資産） | 28 | 1,310,213 | 1,310,213 | 0 |
| 未払金（負債） | 46 | 216,620 | 216,620 | 0 |

全バケットで「期首＋期中の借方－貸方＝残高」が一致。内訳APIに無いIDの元帳行（はぐれ行）は0件。今回の起点だったジャパンカーゴネットワーク有限会社は 期首 1,045,000／期中 2件 -1,045,000／**残高 0** となり、freeeの画面と一致した。

残高も動きも無い取引先は内訳APIが返さないので、内訳が無駄に長くなることはない。

## 制約・注意

- **読み取り（GET）専用**。freeeへの書き込みAPIは一切呼ばない。外部への送信もしない
- 使っているのは freee の**内部API**（`/api/p/reports/trial_balance_sheet`、`/api/p/reports/trial_balance_sheet_element`、`/api/p/reports/general_ledgers/show`）。公開APIではないので、freee側の画面刷新で壊れることがある。壊れたら直す前提のツール
- 品目別の内訳も金額は試算表から取るので必ず合う。品目を使っていない事業所では「未選択」1行だけになる
- 「押し出す」モードでfreeeのレイアウトが崩れる画面があったら、ドロワー上部の「押し出す」ボタンをOFFにすると重ねて表示するモードになる
