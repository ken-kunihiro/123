# MF会計アシスト（Chrome/Brave拡張）

マネーフォワード クラウド会計の仕訳入力ページ用の拡張。機能は4つ。

| 機能 | 何ができるか |
|------|------|
| ⚡ ルール一致一括選択 | 自動仕訳ルールに一致した明細（白）だけを一括チェック |
| 科目ボタンパネル | よく使う勘定科目をワンクリックで選択・確定 |
| 🔍 何費？検索 | 勘定科目辞典「これ、何費？」(nanpi.pages.dev) を小窓で検索 |
| ＋補助科目 / ＋取引先 | 補助科目・取引先をその場で作成して、そのまま仕訳に選択 |

対応ページ:

| ページ | URL | 使える機能 |
|------|------|------|
| 通帳・カード他 | `/transaction_journals` | ⚡ / 科目ボタン / 🔍 |
| ビジネスカテゴリ（ユビレジ等・日次） | `/journalable_dists` | ⚡ / 科目ボタン / 🔍 |
| AI-OCRから入力（クラウドBoxの証憑） | `/voucher_journals/journal_candidates` | 科目ボタン / 🔍 / ＋補助科目・＋取引先 |

⚡ルール一致一括選択は明細一覧を前提にした機能なので、AI-OCRから入力ページには読み込まない（誤作動防止のため `manifest.json` でスクリプトを分けている）。

## インストール（Brave / Chrome共通）

1. `brave://extensions`（Chromeは `chrome://extensions`）を開く
2. 右上の「デベロッパーモード」をONにする
3. 「パッケージ化されていない拡張機能を読み込む」をクリック
4. このフォルダ（`mf-bulk-select-extension`）を選択

更新したときは拡張の「再読み込み」→ MFのページをリロード。

## 1. ルール一致一括選択

「一括登録」ボタンの隣に「⚡ ルール一致を全選択」ボタンが出る。

※ ページ読み込み直後で「一括登録」がまだ描画されていない間だけ、画面**左下**に仮表示され、描画され次第「一括登録」の隣へ自動移動する（右上に仮表示するとMFの「自動ルール」ボタンを塞ぐため。2026-07-28修正）。

- 白（ルール一致で科目がすべて入っている） → チェックする
- 青（MF推定・雲アイコン） → チェックしない（科目を直す可能性があるため）
- 科目未選択 → チェックしない
- 「自動仕訳ルールとして保存」「適格」のチェックボックス → 一切触らない

**登録は自動実行しない。** チェックまでを拡張が行い、「一括登録」ボタンは自分で押す。
細かい挙動・リトライ仕様は `content.js` 冒頭のコメントを参照。

## 2. 科目ボタンパネル

画面右下に「科目ボタン」パネルが出る。

### 使い方

1. 明細行の勘定科目ボタンをクリック（MFのドロップダウンが開く）
2. パネルの科目ボタンをクリック → その科目が選択・確定される
3. ボタンが緑に光れば成功

ドロップダウンが閉じてしまっていても、直前にクリックした勘定科目ボタンを覚えているので、自動で開き直してから選択する。まだ一度も勘定科目欄を触っていない場合は「先に明細行の勘定科目ボタンをクリックしてね」と案内が出る。

- 科目名は**先頭一致**で探す（完全一致を優先）。見つからないと「候補が見つからないよ」と出るので、MFの勘定科目名（正式名称）を確認する
- パネルはヘッダーをドラッグで移動でき、位置は保存される。「−」で折りたたみ
- ビジネスカテゴリページの勘定科目・補助科目ボタンにも同じ仕組みで使える
- **AI-OCRから入力ページ**（`/voucher_journals`）でも使える。一覧で「編集」を押して開く詳細パネルの中の、借方/貸方の勘定科目ボタンをクリックしてからパネルの科目ボタンを押す
  - 詳細パネルでは科目・補助科目・取引先・税区分・インボイスが同じ見た目のボタンで並ぶ。科目以外を開いた状態で押しても「候補が見つからないよ」が出るだけで、誤った値は入らない

### 科目リストの変更

ツールバーの拡張アイコン → テキストエリアに1行1科目（最大10件）→「保存」。MFの画面に即反映される。

初期設定（MF標準の科目名）:
会議費 / 接待交際費 / 旅費交通費 / 通信費 / 備品・消耗品費 / 支払手数料 / 広告宣伝費 / 新聞図書費 / 諸会費 / 支払報酬

※ freee版と科目名が違うことに注意（freee「交際費」→MF「接待交際費」、freee「消耗品費」→MF「備品・消耗品費」、freee「支払報酬料」→MF「支払報酬」）。

※ **科目名は事業所ごとに違う**。初期設定はMF標準の名前なので、勘定科目マスターを独自に組んでいる事業所では合わないことがある（例: ある事業所では「備品・消耗品費」がなく「消耗品費」、「支払報酬」ではなく「支払報酬料」）。候補が見つからないときはこの設定画面で実際の科目名に直す。

※ 設定は `chrome.storage.local` を正、MFページの `localStorage`（`mfkbMirror`）を副として二重に持つ。拡張を入れ直しても副から復元する。起動のたびに正→副へ揃えるので、MFタブを閉じたまま設定を変えても次にMFを開いた時点で同期される。

※ **設定が初期リストに戻る不具合（v1.4.4で修正済み）**: パネルの差し直し用MutationObserverを設定読み込みより先に登録していたため、DOM変化が先に起きた回だけデフォルトの科目リストでパネルが作られ、そのまま固定されていた。Observerの登録を読み込み後に移し、読み込み時に古いパネルを捨てて作り直すようにした。

## 3. 補助科目・取引先のワンクリック追加

パネル下部の「＋補助科目」「＋取引先」。MFの標準フローだと「勘定科目マスターへ移動 → 新規作成 → 仕訳画面に戻る → 再読み込み」の往復が要るところを、ボタン1回に畳む。

### 使い方

1. 詳細パネルの**勘定科目ボタン**をクリック（どの科目の補助を作るかを拡張が判定するため）
2. 「＋補助科目」を押す → 名前を入力 → 確認 → 作成される（「＋取引先」は名前のあとにインボイス登録番号も聞く。登録がなければ空でEnter）
3. 画面が自動で読み込み直され、同じ明細の詳細パネルが復帰して、**勘定科目と作った補助科目の両方が自動で選択される**

リロードで仕訳候補はサーバー側の値に戻るため、補助科目だけでなく**勘定科目も選び直す**（触っていた借方／貸方の組を控えておいて、科目 → 補助科目の順に入れる。すでに正しい科目が入っていればそこは触らない）。

### 仕様と制約

- **リロードは必ず挟まる。** MFはマスターをページ読み込み時の `GET /api/v1/journals/configurations` で一括配信していて、ドロップダウンはそのクライアントキャッシュしか見ない（開いてもAPIを叩かない・詳細パネルを開き直しても再取得しない）ため、リロードなしで新しい補助科目を出す手段がない
- 仕訳候補そのものはサーバー側のデータなので、リロードしても元に戻る。**手で直した内容だけが失われる**ので、作成前に確認ダイアログを出している
- 勘定科目ボタン以外（税区分・インボイス等）を最後に触っていた場合は、マスターに実在する科目名と一致しないので「先に勘定科目ボタンをクリックしてね」で止まる。誤った科目に補助科目を作ることはない
- 同名が既にあるときは作成せずに知らせる
- **補助科目の税区分は親科目と同じにする**（親科目の `defaultExciseId`）。MFのマスター画面の初期値である「不明」で作ると、その補助科目を選んだ瞬間に仕訳側の税区分まで「不明」に書き換わる（2026-09-01 実測。既存の補助科目はいずれも親科目と同じ税区分だった）
- **取引先はインボイス登録番号を空で作ると、MF側で「2023-10-01以降は非適格」扱いになる**（`qualifiedPeriods` が2023-09-30までになる）。控除計算に効くので、適格事業者なら登録番号（T＋13桁）を入れて作る。形式が違うときは送信せずに止める
- 法人番号は空で作る。必要なら取引先マスターで後から補う
- 連携サービスから入力ページでも作成自体はできる（詳細パネルがないので、選択は手動になる）

### 実装メモ

| 対象 | POST先 | 主なパラメータ |
|------|------|------|
| 補助科目 | `/sub_items?cti=…` | `sub_item[item_id]`（勘定科目の `plainId`）/ `sub_item[name]` / `sub_item[excise_id]` |
| 取引先 | `/trade_partners?cti=…` | `trade_partner_form[trade_partner][name]` ほか |

- CSRFトークンは仕訳画面の `meta[name="csrf-token"]` から取る（マスター画面へ行く必要はない）
- 勘定科目の `plainId`・税区分の `plainId` は事業所ごとに違うので、都度 `configurations` から引く（科目は名前で、税区分は科目の `defaultExciseId` で）
- MFはPOSTの成否をJS片やHTMLでしか返さないため、**作成後に `configurations` を取り直して実在を確かめる**ことで成否を判定している
- 実測（2026-09-01）: 補助科目のPOSTは**作成に成功していてもHTTP 400が返る**（取引先は200）。ステータスで判定していたら成功を失敗と誤判定していた。実在確認方式が正しい
- 作成後は「詳細パネルの何組目・どの科目・何を選ぶか」を `mfkbPending` として保存してからリロードし、復帰後に科目→補助科目の順で自動選択する（2分で失効）。組が見つからないときは科目名一致の組にフォールバックする
- **リロード直後はボタンだけ先に並んでラベルが後から入る**ので、「ボタンが現れたら進む」待ち方だと科目が空のうちに走って失敗する。控えた勘定科目のラベルが実際に出そろうまで待つ（最大20秒・200ms間隔）。それでも出なければ控えた組に自分で科目を入れ直す。補助科目／取引先の選択は失敗したら800ms待って一度だけやり直す（v1.4.3）

## 4. 何費？検索（🔍）

パネルのヘッダーの🔍ボタンから「これ、何費？」を小窓で開く。検索語は次の優先順:

1. **ページ上で選択中のテキスト**: 摘要の一部をマウスで選択してから🔍
2. **最後に触った明細行の摘要**: 半角カナ→全角変換・長音補正・「/」「（」以降やノイズの除去をした店名候補（例:「ﾃﾞﾆ-ｽﾞ（DENNYS）」→「デニーズ」）
   - AI-OCRから入力ページでは明細行の摘要欄がないため、最後に触った科目ボタンから祖先をたどって詳細パネル内の摘要textareaを拾う
3. **手入力ダイアログ**: どちらもなければ入力ダイアログが出る

- 小窓はウィンドウ名を使い回すので、連続で調べても増えない
- 通信先は nanpi.pages.dev のみ。MFのデータを外部に送ることはない（検索語として渡すのは上記の語だけ）

## ファイル構成

| ファイル | 役割 |
|------|------|
| `manifest.json` | 拡張機能の設定（Manifest V3） |
| `content.js` | ルール一致一括選択 |
| `kamoku.js` | 科目ボタンパネル＋補助科目・取引先の追加＋何費？検索 |
| `popup.html` / `popup.js` | 科目リスト設定画面 |

## 注意事項

- MF会計の画面構造（DOM）に依存している。MF側の画面が大きく変わると動かなくなる可能性がある
  - 勘定科目の選択は「ボタンclick → body直下のポータル `dropDownListItems` → 項目click」で実現している（2026-07実機検証）
  - AI-OCRから入力ページの科目ボタンは `button[class*="selectedChoiceLabel"]` で追跡している（2026-09-01 実機検証）
- 科目を選択すると、その行はMF推定（雲アイコン）から手動選択扱いに変わる。これはMFの仕様どおりの挙動
- ＋補助科目・＋取引先は**マスターに実データを作る**。取り消したいときはMFの勘定科目マスター／取引先マスターから削除・無効化する
